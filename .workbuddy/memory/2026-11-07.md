## chrome.dll 逆向：Wayfern CDP Token 授权机制（已完成字符串级还原）

**目标**：`D:\bian\151.0.7922.76\chrome.dll`（359MB，Chromium 151.0.7922.76 定制版 = Wayfern 反检测浏览器）。用户真实目标：理解 CDP token 机制以验证到自己的服务器。

**关键结论**：
- chrome.dll 是 Wayfern（bwbrowser/Donut 生态的 Chromium 定制版），含自定义 CDP 域 `Wayfern.*`（getFingerprint/setFingerprint/resetFingerprint 等）。
- "CDP token" = **wayfernToken**：调用方传入的跨 OS 指纹授权凭证（CDP 参数 `wayfernToken` 或环境变量 `WAYFERN_TOKEN`）。仅**跨 OS 指纹**（付费计划 pro/team）需要；同 OS 指纹切换不需要。
- 验证流程（`WayfernHandler::VerifyTokenForPlan`，源文件 `content\browser\devtools\protocol\wayfern_handler.cc`）：POST `https://api.donutbrowser.com/api/auth/wayfern-generate`，UA `DonutBrowser-Wayfern/<ver>`，带重试；响应为**签名响应**（本地验签，公钥内置 dll）；成功得到 plan+有效期并缓存（`wayfern-entitlement-cache-dir`，字段 token_sha256/retry_not_before/request_nonce/sig）。
- 自建服务器三道坎：① dll 内 URL 硬编码（可补丁字符串或 DNS）；② 响应验签公钥内置（运营方有私钥则直接自签，否则需补丁验签分支）；③ 响应格式须含 plan/expires/sig 等字段。

## 【端到端打通】Wayfern 跨 OS 指纹授权整套握手契约已逆向（2026-11-07 深夜）

**目标**：patch 后的浏览器 vs 自家 verify.php 真实握手跑通，实现"在服务器搭建跨端指纹"。

**核心契约（Frida + Capstone 逆向确认，陈旧的"token 直插"理解已废弃）**：
- 握手链路：浏览器 POST → verify.php（Ed25519 分离签名）→ 响应 JSON `integrity.data/sig` 结构。
- 浏览器对 `base64_decode(data)` 按 `|` 切分，字段布局**必须**为 5 段：
  `nonce | timestamp | exp | token[0:16] | plan`
  - f[0]=nonce=浏览器算出的指纹哈希（32 位小写 hex，须与内核算出的指纹一致）
  - f[2]=exp 须在「内核当前时间 +300s」内
  - f[3]：5~6 字段走路径 B（`0x48eb5a1`）→ 必须等于 wayfernToken 的**前 16 字符**（`substr($token,0,16)`，内核 pcmpeqb 16 字节精确比对）；≥7 字段才走路径 A → `sha256_hex(token)`（64hex）
  - f[4]=plan 码："0"/"1"
- `0x802f3e0` 是 hex-encoder（非哈希）；signature 验签用新内嵌公钥，Ed25519 分离签名基于 base64 原文。

**关键修复点**：
- verify.php 的 blob 由「token 直插」改为 `"$nonce|$ts|$exp|" . substr($token,0,16) . "|$plan_code"`。
- plan 码：JWT 有效时返回 `'1'`（原两分支都硬编码 '0'，被浏览器判为 free）。
- 部署：`/www/wwwroot/www.yacm.xin/tk/api_auth_wayfern_verify.php`（bak：`.bak_20261107`、`.bak_base64url_20261107_221049`、`.bak_base64url_20261107_215943`）。
