## 暗色问题「在创建用户数据时根因」治本修复（接 11-10 深夜）

- **根因**：创建 profile 时生成的 fingerprint（metadata.json）缺省 `prefersDarkMode` 字段 → 内核把页面 prefers-color-scheme 伪装成宿主「系统表面」主题（App 浅/System 暗 → 页面恒暗）。

  2. `browser_runner.rs` 本地启动路径补 `reapply_fingerprint_to_page_targets`（仅云启动 bwbrowser_cloud 原有；补本地，覆盖启动后手工导航新 tab 的暗色）。

## 「健康检查正常但实际没登录」修复（2026-11-11 07:30 前后）
- 用户报：健康检查显示正常，浏览器打开实际未恢复登录。日志（bwbrowser_debug.log）实锤 YouTube 账号 3873：
  本地 429 分→保留本地→导航 studio.youtube.com→探测 "Session detected" Valid→回传云端；07:03 还出现过 "Cookie mismatch page detected; treating session as valid"。
- **根因两处（cookie_health.rs YouTube 规则 + 通用 redirect 分支）**：
  1. session_indicators=["INNERTUBE_API_KEY","clientScript"]——这两个字符串在 www.youtube.com **未登录访客的 HTML 里也有**（页面 JS 内嵌 API key），首页探测未登录也命中 "Session detected"→Valid 假阳性。
  2. Google /CookieMismatch 重定向被有意判 Valid（原注释以为"账号侧会话还活着"），但浏览器里那是"验证是您本人"页=实际不可用，且坏 cookie 被当正常回传云端。
- **修复（cookie_health.rs，需重编译）**：
  1. YouTube 规则探测 URL www.youtube.com → **https://www.youtube.com/account**（未登录 30x→ServiceLogin→login indicator "login" 命中→Expired；登录 200→Valid）。verdict 探测不跟随重定向（Policy::none），两种情形判定都正确。
  2. CookieMismatch 分支 Valid → **Expired**（"Google CookieMismatch page (device verification required)"），注释重写：浏览器实际不可用，不再把坏会话当正常回传。
- 云端核查：VPS platform_config.json 的 platforms.youtube **无 cookie_probe**（只有 guanying 有）→ 本地规则生效，修改有效。
- 边界说明：此修复让判定如实（不再假正常、不再污染云端 cookie），但 Google 设备校验（CookieMismatch）本身需用户在浏览器里人工完成验证，程序无法自动恢复该类会话。
- 另：cargo 报 E0596（fingerprint 需 mut）已修——generate_fingerprint_config 解构改 `let (mut fingerprint, ...)`。
